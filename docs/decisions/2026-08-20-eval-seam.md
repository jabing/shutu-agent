# 2026-08-20 任务评测接缝（eval capability seam）

状态：候选 → 实施中（Eval-1 派发）
关联：M5b（subagent 派发）、M6b（plan 任务分解）、M6d（interact 人工回退）、M8（llm 多 provider）、M7/M8/M9（D2 接缝、D3 事件、D5 串行、D10 默认关）

## 背景

- 用户问："Agent 能力实现后能否像 dsh 一样做复杂任务分解/派发/评测？"（记录 `893073a`）。核对结论：**分解**（M6b plan：goal→plan→todo + `plan_*`）与**派发**（M5b subagent + M5a jobs + M6a schedule）**已是完成的闭环**；**评测是真正缺口**——当前只有 子代理自报报告 + 父模型判断 + `interact` 人工审批，**无独立自动评测接缝**（dsh 同样无开箱即用 eval，评测主要报告驱动，非其专有能力）。
- 用户拍板（`893073a`）：**记入候选**（编译期接缝，非运行时插件）；**建议排期 M9 之后、KB 全量之前**。设计方向原文："`eval` 接缝（EvalProvider：规则断言 / LLM judge / 人工回退 + `eval_*` 工具 + `eval/*` 事件 + config 默认关 D10）；评测标准来源 = `plan_todo` 条目带验收标准字段 → 派发随任务传给子代理 → 评测器对照验收标准（规则断言优先、LLM judge 兜底、无法自动判定落 `interact` 人工），形成"分解→派发→评测→（不合格重派）"闭环。"
- 本 ADR 把该方向落成可实施契约。

## 决策

### D-EVAL-1 域模型

- `Verdict`：`pass` / `fail` / `manual`（无法自动判定，需人工）。
- `EvalRecord`：`{ID, TaskID string, Criteria []string, Output string（有界摘要）, Verdict, Reason string, EvaluatorKind string, CreatedAt}`。
- 评测历史**内存存储**（照 plan/subagent/interact 的 mem Provider 心智，D5）：进程重启即清，不落盘。评测记录是运行期判断依据，不是持久知识。

### D-EVAL-2 D2 三件套：eval seam

- `internal/eval`：`Evaluator` 接口 `Evaluate(ctx, output string, criteria []string) (Verdict, reason string, err error)` + `Engine`（Service：`Evaluate(ctx, taskID, output, criteria) (EvalRecord, error)` / `List` / `Get`）+ `Provider`（dumb 存储，mem 默认）+ `Close`。
- **可插拔**：换评测器（换 Provider/换 judge 策略）不改消费方（D2）。
- 消费方（`eval_*` 工具、`eval/*` 事件）只依赖 seam 接口。

### D-EVAL-3 评测器编排（规则断言优先 → LLM judge 兜底 → 人工回退）

- criteria 条目可带模式前缀（每条约 100 字内，模型在 plan_todo 写验收标准时声明）：
  - 无前缀 / `contains:` → **规则断言**：output 必须包含该文本（确定性，零模型调用）。
  - `not:` → 规则断言反向：output 必须**不**包含该文本。
  - `llm:` → 该条走 **LLM judge**。
  - `manual:` → 该条强制**人工回退**。
- 编排顺序（Composite）：
  1. 先跑全部规则断言（contains/not）：任一违例 → `fail`（带违例条目理由）。
  2. 全过且存在 `manual:` 条目 → `manual`。
  3. 全过且存在 `llm:` 条目 → 打包全部 `llm:` 条目给 LLM judge（JSON 输出 `{verdict: pass|fail|manual, reason}`）。
  4. 无任何 llm/manual 条目且规则全过 → `pass`。
- LLM judge 复用注入的 `llm.LLM`（照 compaction/skill 心智，D8：不重复实现 provider 逻辑）；judge 提示词内置（只判 verdict + 一句理由），不可配置为任意文本（防提示注入，模型产出仅作为判断输入）。
- 人工回退复用 `interact.Engine`（D-EVAL-7）。

### D-EVAL-4 验收标准来源与派发传递

- `plan.Todo` 加 `Acceptance []string` 字段（验收标准列表）；`Engine.AddTodo` 加 `acceptance []string` 参数；`plan_todo` 工具 schema 加可选 `acceptance` 数组（模型在规划时直接写验收标准）；`plan/*` 事件载荷带 acceptance（D3）。
- `subagent.StartRequest` 加 `AcceptanceCriteria []string`（可选）；SpawnProvider 把验收标准注入子代理 prompt 尾部"验收标准（交付自检）"段；`subagent_spawn` 工具 schema 加可选 `acceptance_criteria` 数组。
- **闭环由模型驱动，不干预 loop（D4）**：`eval_run` 返回 fail → 模型重新 `subagent_spawn` 重派。评测接缝只提供评测能力，不做 loop 内自动重派（D4 纪律：turn/step 结构不动）。

### D-EVAL-5 事件与输出边界（D3）

- `eval/run` 事件：评测完成落库 `{id, task_id, verdict, reason, evaluator_kind, criteria 数}`——**只记摘要，不落 output 全文**（防爆炸，照 job/done 的 summaryHead 心智）。
- 完整 output + 判定依据经 `eval_*` 工具的 `tool/result` 返回给模型（模型实际看到 ⇒ 已满足 D3）。

### D-EVAL-6 config 与默认关（D10）

- `eval:` 段：`enabled`（默认 false）、`manual_fallback`（默认 true；false 时 LLM 判 manual 视为 fail）、`max_records`（默认 100，历史内存上限）。
- `enabled=false` → 零工具、零事件、零副作用；`evalToolNames` 白名单自动追加（照 `<cap>ToolNames` 模式）。

### D-EVAL-7 人工回退复用 interact

- `manual` 判定创建 `interact.Request{Prompt: "评估任务 <taskID> 交付是否满足验收标准…", ToolName: "eval_manual", Args: 摘要}`；`approved` → pass，`rejected` → fail，expired → manual（保持待定）。
- 复用既有 interact 审批通道（`interact_ask`/`interact_status`），不新建审批 UI。

## 里程碑分段

- **Eval-1**：`internal/eval` 包（Evaluator 接口 + rule/llm/manual 三实现 + Composite 编排 + Engine + mem Provider）+ 单测（mock LLM / mock interact 全分支）。
- **Eval-2**：plan.Todo.Acceptance + AddTodo 扩展 + plan_todo 工具 acceptance + subagent.StartRequest.AcceptanceCriteria + SpawnProvider prompt 注入 + subagent_spawn 工具 acceptance_criteria。
- **Eval-3**：config `eval:` 段 + session `eval/run` 事件 + `eval_run`/`eval_result`/`eval_list` 工具 + cmd/pa 接线 + 接线测试 + 冒烟。

## 验收标准（全部通过才算完成）

1. `go vet/test/build ./...` 全绿。
2. 规则断言：contains/not 判定确定性正确（零模型调用）；违例即 fail。
3. LLM judge：mock LLM 返回 pass/fail/manual → 正确映射；manual_fallback=false 时 LLM manual → fail。
4. 人工回退：无法自动判定 → interact Request 创建（toolName=eval_manual）；approved→pass / rejected→fail。
5. plan_todo 带 acceptance 落库并可经 plan_list 回读；subagent_spawn 带 acceptance_criteria 注入子代理 prompt（断言子代理首条消息含验收标准段）。
6. eval/run 事件落库（摘要，无 output 全文）；eval_result/eval_list 可查历史；历史内存上限生效。
7. 默认关（enabled=false 无工具无事件无副作用）。
8. 不改 `internal/loop/loop.go` turn/step 结构（D4）；主循环串行（D5）；零新依赖；CGO-free。
