# 2026-08-20 M9 持久终端会话（terminal capability seam）

状态：候选 → 实施中（M9-1 派发）
关联：M5a（jobs 心智）、M7/M8（D2 接缝、D3 事件、D5 串行、D10 默认关）

## 背景

- M5a 的 `job_*` 工具是**一次性** shell 调用：每次 `job_start` 起新 shell、跑完即退，进程间状态（cwd、环境、一个 REPL 的上下文）不保留。
- 需求：**持久终端会话**——一个跨命令存活、可写 stdin、读 stdout/stderr、可中断的交互式进程（REPL、ssh、数据库 TUI、长任务）。模型与用户都能驱动。
- dsh 范式（`packages/terminal/terminal-bash/src/session.ts` 7078918 系）：持久 PTY 会话 + 有界 scrollback（字节+行双上限、UTF-8 安全截断、dropped 标记）+ consume/snapshot 双读 + send 就绪判定（prompt 检测 / 静默推断 idle / 绝对 timeout）+ 生命周期（initialize → send → read → signal → close）。
- **平台约束（决定性的）**：本项目在 **Windows + Go stdlib + 零新依赖 + CGO-free** 下运行。Go stdlib 不暴露 Windows ConPTY（`CreatePseudoConsole`），`creack/pty` 等不支持 Windows；dsh 本身也无 Windows 真 PTY（全 Linux bash / 远程 e2b）。

## 决策

### D-M9-1 持久 shell 伪终端，不做真 ConPTY

- Windows 下用**持久子进程 + 标准管道**（stdin/stdout/stderr）实现终端会话，而非真 PTY（ConPTY 不可达，见背景）。
- Shell 默认 `cmd.exe /Q`（关闭 echo 的提示符噪声；`/Q` 关闭 echo off 提示符回显），可配置。
- **诚实标注局限（写进帮助与文档）**：无 TTY 语义 —— 全屏 TUI（vim/htop）不能工作；Windows 管道下无控制台 Ctrl+C 事件，`interrupt` 是尽力而为（向 stdin 写 `\x03`），可靠中断靠 `stop`（终止会话）。
- 这满足核心价值：**跨命令状态保持**（cwd/环境/交互式 REPL 上下文），这是持久终端的第一诉求。

### D-M9-2 D2 三件套：terminal seam

- `internal/terminal`：`Session` 是持久的 shell 子进程句柄（id/owner/startedAt/status），方法 `Write(text, submit)` / `Read(offset, count)` / `Consume()` / `Signal(kind)` / `Close()`；`Registry`（单活跃会话 + owner 校验，照 jobs.Local 心智）。
- 模型工具五件套 `terminal_start/terminal_write/terminal_read/terminal_signal/terminal_stop`（照 job_* 同款），REPL `/term` 命令组。
- 消费方（loop）不感知 terminal（组合根注入工具与事件，D4）。

### D-M9-3 有界 scrollback（dsh BoundedTextBuffer 移植）

- 会话缓冲：字节上限 + 行数上限双约束，UTF-8 安全截断（保尾丢最早），`truncated` 标记。
- 双读语义：`Read(offset, count)` 快照（回放/查看历史）；`Consume()` 消费 delta（工具每次读取自上次以来的新输出）。
- 输出永不落会话日志正文（防爆炸）：D3 事件只记 `terminal/start` / `terminal/stop` 元数据（照 job/* 模式）。

### D-M9-4 就绪判定（写后返回时机）

- `Write` 阻塞直到三态之一：**静默推断**（自最后输出起 idle 静默 `idle_ms`，默认 500ms）→ `stdin_read`；**绝对 timeout**（`timeout_ms`，默认 30s）→ `timeout`；**进程退出** → `session_exit`。返回这期间的新输出。
- 不做 prompt 解析/注入（Windows 提示符形态不稳），静默推断是唯一就绪信号（dsh 的 `inferred_idle` 同款）。长任务靠 timeout 兜底（模型可再 read）。

### D-M9-5 生命周期与并发

- 单活跃会话（owner = 当前 session id）：`terminal_write/read` 串行（D5）；`terminal_start` 在活跃会话上报"已存在"（或自动停旧起新——由工具语义定，倾向显式报错）。
- `Close`：终止子进程树（Windows 杀直接子进程，照 M5a `killJobTree` 心智；残留孙进程为文档化残余风险）+ 等退出 + 释放缓冲；进程退出自动标记 `exited`。
- 全部副作用归组合根/工具生命周期，无泄漏 goroutine（照 jobs 同款）。

### D-M9-6 config 与默认关（D10）

- `terminal:` 段：`enabled`（默认 false）、`shell`（默认 `cmd.exe`）、`scrollback_max_bytes`（默认 64KiB）、`scrollback_lines`（默认 2000）、`read_idle_ms`（默认 500）、`read_timeout_ms`（默认 30s）、`max_concurrent_sessions`（默认 1）。
- 凭证纪律：子进程环境 scrubbed（照 `scrubbedEnv`，不继承 agent 密钥）。

## 里程碑分段

- **M9-1**：`internal/terminal` 包（Session + 有界缓冲 + Windows 实现 + 就绪判定）+ 单测（真实子进程，短 idle 保持测试稳定）。
- **M9-2**：config `terminal:` 段 + D3 事件 + 模型工具五件套 + `/term` REPL 命令 + wiring + 冒烟。

## 验收标准（全部通过才算完成）

1. `go vet/test/build ./...` 全绿。
2. 持久会话跨命令保持 cwd/环境；交互式 REPL（`cmd /Q` 起 `python -i` 或 `node`）可 `terminal_write` 代码 → `terminal_read` 输出，多次往返不丢上下文。
3. 有界缓冲：超限截断（保尾）+ `truncated` 标记；`Read(offset,count)` 与 `Consume()` 语义正确。
4. 就绪判定：短命令快返（idle）、长任务到 timeout 仍返回、进程退出报 `session_exit`。
5. 默认关（`enabled=false` 无工具无命令无副作用）；凭证 scrubbed。
6. `terminal_signal(stop)` 终止进程树并释放；`interrupt` 在 Windows 标注"尽力而为"。
7. 不改 `internal/loop/loop.go` turn/step 结构（D4）；主循环串行（D5）；零新依赖；CGO-free。
8. Windows 局限（无真 TTY / Ctrl+C 近似）写入帮助与设计文档，不假装支持全屏 TUI。
